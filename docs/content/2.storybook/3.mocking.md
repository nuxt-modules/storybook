---
title: Mocking
description: Mock Nuxt auto-imports, components and server endpoints in your stories.
---

`@storybook-vue/nuxt` ships the mocking helpers of `@nuxt/test-utils`, adapted to stories. Call them at the top level of a story file: they apply to every story of that file.

## `mockNuxtImport`

Replaces an auto-import (composable or util) for the stories of the file, and returns its [`storybook/test`](https://storybook.js.org/docs/writing-tests) spy.

```ts [components/MyGreeting.stories.ts]
import { mockNuxtImport } from '@storybook-vue/nuxt'
import { expect, within } from 'storybook/test'

import preview from '../.storybook/preview'
import MyGreeting from './MyGreeting.vue'

const useGreeting = mockNuxtImport(
  'useGreeting',
  () => (name: string) => `Bonjour ${name}`,
)

const meta = preview.meta({ component: MyGreeting, args: { name: 'Nuxt' } })

export const Mocked = meta.story({
  async play({ canvasElement }) {
    await expect(within(canvasElement).getByText('Bonjour Nuxt')).toBeVisible()
    await expect(useGreeting).toHaveBeenCalledWith('Nuxt')
  },
})
```

The name must be a string literal, and each name can only be mocked once per file. Without a factory, the import keeps its implementation and is only spied on.

## `mockComponent`

Replaces a Nuxt component for the stories of the file. The factory returns a component, or imports a `.vue` file.

```ts [components/MyProfile.stories.ts]
import { mockComponent } from '@storybook-vue/nuxt'

mockComponent('MyAvatar', () => import('./MyAvatar.mock.vue'))
```

## `registerEndpoint`

Answers requests made with `$fetch`, `useFetch` or `fetch` from inside the preview, with an [h3](https://h3.dev) handler running on your project's h3 version.

```ts [components/MyUsers.stories.ts]
import { registerEndpoint } from '@storybook-vue/nuxt'

// Every story of this file
registerEndpoint('/api/users', () => ['Alice', 'Bob'])

export const Empty = meta.story({
  // This story only, before the endpoints of the file
  beforeEach(context) {
    registerEndpoint(context, '/api/users', () => [])
  },
})

export const Created = meta.story({
  // Or with the story parameters
  parameters: {
    nuxt: {
      endpoints: {
        '/api/users': { method: 'POST', handler: () => ({ ok: true }) },
      },
    },
  },
})
```

URLs match like in `@nuxt/test-utils`: the URL as fetched, with or without its query, so absolute URLs of other origins can be mocked too. Unlike `@nuxt/test-utils`, a same-origin URL without endpoint reaches the dev server instead of answering 404. An endpoint can also set a `method`, and `once` to be removed after its first call.

## Docs pages

Mocks and endpoints apply per story file, and per story, even when a docs page renders stories of several files at once. The story is known during the component setup and render, in plugins and middleware, and for `$fetch` and `useFetch` requests.

On a docs page rendering stories of several files inline, a mocked auto-import called, or a request to a registered endpoint made, outside of the Nuxt context (an event handler, a timer, or after an `await` in an async callback) uses the mocks of the story the user last interacted with: a click handler gets the mocks of the clicked story.

Before any interaction, such a call (from an effect or a timer) throws a `NuxtMocksSharedOnDocsPageError`: the story whose mocks apply is unknown there. Render the stories of these files in their own iframe:

```ts [components/MyUsers.stories.ts]
const meta = preview.meta({
  component: MyUsers,
  parameters: { docs: { story: { inline: false } } },
})
```

Or make the call or the request during the component setup.

### Configuring a spy

The spy returned by `mockNuxtImport` is one object for the whole page, so inline stories share it. When a story configures it in its setup, such as with `mockReturnValue` in a `beforeEach`, while the docs page renders another story, a `NuxtSpySharedOnDocsPageError` is thrown instead of rendering a story with the implementation of another one:

```ts [components/MyGreeting.stories.ts]
const useGreeting = mockNuxtImport('useGreeting')

export const Spanish = meta.story({
  beforeEach() {
    // Throws on a docs page rendering the other stories of the file inline
    useGreeting.mockReturnValue('Hola')
  },
})
```

Render the stories of the file in their own iframe with `docs.story.inline: false`, as above, or set the implementation with the factory of `mockNuxtImport`, which applies per story file.

A story rendered alone, and a docs page rendering a single story, configure the spy freely. Assertions on the calls of the spy are not checked: on an inline docs page, they see the calls of every story.
