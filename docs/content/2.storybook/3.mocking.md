---
title: Mocking
description: Mock Nuxt auto-imports, components and server endpoints in your stories.
---

`@storybook-vue/nuxt` ships the mocking helpers of `@nuxt/test-utils`, adapted to stories. Called at the top level of a story file, they apply to every story of that file. Called in a hook of a story, they apply to that story only.

## `mockNuxtImport`

Replaces an auto-import (composable or util) for the stories of the file, and returns its [`storybook/test`](https://storybook.js.org/docs/writing-tests) spy.

```ts [components/MyGreeting.stories.ts]
import { mockNuxtImport } from '@storybook-vue/nuxt'
import { expect, within } from 'storybook/test'

import preview from '../.storybook/preview'
import MyGreeting from './MyGreeting.vue'

const useGreeting = mockNuxtImport(
  'useGreeting',
  () => (name: string) => `Bonjour ${name}`,
)

const meta = preview.meta({ component: MyGreeting, args: { name: 'Nuxt' } })

export const Mocked = meta.story({
  async play({ canvasElement }) {
    await expect(within(canvasElement).getByText('Bonjour Nuxt')).toBeVisible()
    await expect(useGreeting).toHaveBeenCalledWith('Nuxt')
  },
})
```

Like in `@nuxt/test-utils`, the factory can be async, and the import can be named by itself instead of a string:

```ts [components/MyRouting.stories.ts]
import { mockNuxtImport } from '@storybook-vue/nuxt'
import { useRoute } from '#imports'

mockNuxtImport(useRoute, () => () => ({ fullPath: '/mocked' }))
```

The name must be a string literal or the import itself, and each name can only be mocked once per file. Without a factory, the import keeps its implementation and is only spied on.

Like a hoisted `vi.mock`, a factory runs once, when the story file loads: the mock is in place before the `loaders`, `beforeEach` and `play` of its stories run.

## `mockComponent`

Replaces a Nuxt component for the stories of the file. It takes the mock component, or a factory returning it or importing a `.vue` file.

```ts [components/MyProfile.stories.ts]
import { mockComponent } from '@storybook-vue/nuxt'

mockComponent('MyAvatar', () => import('./MyAvatar.mock.vue'))
```

Like in `@nuxt/test-utils`, the component can also be named in kebab case, or by its path, relative to the story file or with an alias:

```ts [components/MyProfile.stories.ts]
import { h } from 'vue'

mockComponent('~/components/MyAvatar.vue', {
  props: { name: String },
  setup: (props) => () => h('span', `👤 ${props.name}`),
})
```

The name must be a string literal, and it must name a Nuxt component.

## Story mocks

Unlike in `@nuxt/test-utils`, the mock functions can be called in the `loaders`, `beforeEach` and `play` written in a story file. They then apply to that story only, over the mocks of the file:

```ts [components/MyGreeting.stories.ts]
export const German = meta.story({
  beforeEach() {
    mockNuxtImport('useGreeting', () => (name) => `Hallo ${name}`)
    mockComponent('MyAvatar', () => import('./MyAvatar.german.vue'))
    registerEndpoint('/api/users', () => ['Hans'])
  },
})
```

The names are still string literals, read at build time. `mockComponent` has to run before the story renders, in `beforeEach` or before `mount()` in `play`: it throws afterwards. In a helper called after an `await`, or in a hook of `.storybook/preview.ts`, the story is unknown and the mock functions throw: `registerEndpoint` takes the story context as first argument there.

## `registerEndpoint`

Answers requests made with `$fetch`, `useFetch` or `fetch` from inside the preview, with an [h3](https://h3.dev) handler running on your project's h3 version.

```ts [components/MyUsers.stories.ts]
import { registerEndpoint } from '@storybook-vue/nuxt'

// Every story of this file
registerEndpoint('/api/users', () => ['Alice', 'Bob'])

export const Empty = meta.story({
  // This story only, before the endpoints of the file
  beforeEach() {
    registerEndpoint('/api/users', () => [])
  },
})

export const Created = meta.story({
  // Or with the story parameters
  parameters: {
    nuxt: {
      endpoints: {
        '/api/users': { method: 'POST', handler: () => ({ ok: true }) },
      },
    },
  },
})
```

URLs match like in `@nuxt/test-utils`: the URL as fetched, with or without its query, so absolute URLs of other origins can be mocked too. Unlike `@nuxt/test-utils`, a same-origin URL without endpoint reaches the dev server instead of answering 404. An endpoint can also set a `method`, and `once` to be removed after its first call.

## Navigation

A story stays on its route: router navigations, `navigateTo(url, { external: true })`, `navigateTo(url, { open })` and clicks on links to other sites are blocked, and reported to the `navigation` spy instead:

```ts [components/MyNavigate.stories.ts]
import { navigation } from '@storybook-vue/nuxt'
import { expect, userEvent, within } from 'storybook/test'

export const Docs = meta.story({
  async play({ canvasElement }) {
    await userEvent.click(within(canvasElement).getByRole('button'))
    await expect(navigation).toHaveBeenCalledWith('https://nuxt.com/docs')
  },
})

// Navigates for real
export const Allowed = meta.story({
  parameters: { nuxt: { navigation: true } },
})
```

## Docs pages

Mocks and endpoints apply per story file, and per story, even when a docs page renders stories of several files at once. The story is known during the component setup and render, in plugins and middleware, and for `$fetch` and `useFetch` requests.

On a docs page rendering stories of several files inline, a mocked auto-import called, or a request to a registered endpoint made, outside of the Nuxt context (an event handler, a timer, or after an `await` in an async callback) uses the mocks of the story the user last interacted with: a click handler gets the mocks of the clicked story.

Before any interaction, such a call (from an effect or a timer) throws a `NuxtMocksSharedOnDocsPageError`: the story whose mocks apply is unknown there. Render the stories of these files in their own iframe:

```ts [components/MyUsers.stories.ts]
const meta = preview.meta({
  component: MyUsers,
  parameters: { docs: { story: { inline: false } } },
})
```

Or make the call or the request during the component setup.

### Spies

Each story has its own spy of a mocked auto-import: the implementation a story sets, and the calls it asserts on, are its own, also on a docs page rendering several stories inline.

```ts [components/MyGreeting.stories.ts]
const useGreeting = mockNuxtImport('useGreeting')

export const Spanish = meta.story({
  async beforeEach() {
    // For this story only
    useGreeting.mockReturnValue('Hola')
  },
  async play() {
    // The calls of this story only
    await expect(useGreeting).toHaveBeenCalledOnce()
  },
})
```

The story using the spy is known:

- in the `beforeEach`, `play`, `loaders` and `afterEach` written in the story file, also after an `await` of theirs
- during the component setup and render, in plugins and middleware
- when the page renders a single story
- after an interaction with a story: a click handler uses the spy of the clicked story

The hooks are found by their name in the story files calling a mock function. Set other names with the `storyHooks` option of the framework, which replaces the default ones:

```ts [.storybook/main.ts]
export default defineMain({
  framework: {
    name: '@storybook-vue/nuxt',
    options: {
      storyHooks: ['afterEach', 'beforeEach', 'loaders', 'play', 'setUp'],
    },
  },
})
```

On a docs page rendering several stories inline, a spy configured anywhere else throws a `NuxtSpySharedOnDocsPageError`, as its story is unknown. This is the case after an `await` inside a helper called by a hook, or of a hook of `.storybook/preview.ts`:

```ts [components/MyGreeting.stories.ts]
async function setUp() {
  await somethingElse()
  // Throws on a docs page rendering several stories inline
  useGreeting.mockReturnValue('Hola')
}

export const Spanish = meta.story({ beforeEach: setUp })
```

A spy called there (from a timer, before any interaction) throws too, once a story of the page configured it. Configure the spy in the hook itself, or render the stories of the file in their own iframe with `docs.story.inline: false`, as above.
